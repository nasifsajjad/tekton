# Tekton Global Trading & Services — Website

Four-page industrial site for **Tekton Global Trading & Services** (Kingdom of Bahrain): safety-yellow and black surfaces, single-weight display type, pill buttons, fluid type scales, and a motion background in the hero.

Stack: **Next.js 16** (App Router, Turbopack), **Tailwind CSS v4**, file-based CMS. No database, no third-party services.

## Pages

| Route | What's on it |
|-------|--------------|
| `/` | Homepage: video/motion hero, platform + trust sections, statement band, Insights & Applications cards, Supply Line tabs with accordions, Why band, yellow callout row |
| `/products` | Product range with category tabs (5 groups, 18 categories) |
| `/contact` | Contact details + quote request form (opens prefilled email) |
| `/about` | Company story, stats, working principles — the growth page for future content |
| `/admin` | Site editor (password-protected, hidden from search engines) |

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
```

## Site editor (CMS)

Every piece of text on all four pages lives in `data/content.json` and is editable at **`/admin`** — grouped by page, with add/remove for lists (product categories, tabs, cards, stats). Press **Save & Publish** and all pages update at once.

### Security

- Password from `ADMIN_PASSWORD` (`.env.local`, see `env.example`). In production the editor is **locked until this is set** — there is no default password outside development.
- Login is rate-limited: 5 failed attempts per IP per 15 minutes.
- Session is an HMAC-signed, `httpOnly`, `secure`, `SameSite` cookie. Password comparison is constant-time.
- `/admin` is `noindex` and disallowed in `robots.txt`.
- Security headers set globally: `X-Frame-Options: DENY`, `nosniff`, referrer and permissions policies.

## Media

Photos and the hero video are drop-in files under `public/media/`. Every slot expects a fixed filename (e.g. `hero.mp4`, `home-platform.jpg`, `insight-1.jpg`); if a file is missing, its slot renders a striped placeholder naming the exact file it expects. Replacing a file swaps the image on the next page load — no code changes. Keep images under ~400 KB and match the ratio shown on the placeholder.

## SEO & performance

- Per-page titles, descriptions, canonical URLs, OpenGraph and Twitter cards, all fed from the CMS content
- `sitemap.xml` and `robots.txt` generated by the app
- Organization JSON-LD structured data
- All public pages prerendered as static HTML, revalidated when the CMS saves
- Fonts self-hosted via `next/font`; images lazy-loaded with reserved aspect ratios (no layout shift)
- Set `NEXT_PUBLIC_SITE_URL` in production for correct canonical/sitemap URLs

## Production

```bash
npm run build
npm start
```

> **Hosting note:** the CMS writes to `data/content.json` on disk, so deploy somewhere with a persistent writable filesystem (VPS, Docker, Railway/Render disk). On read-only serverless hosts the site works but Save & Publish will fail; swap `src/lib/content.ts` to a database if you must deploy there.

## Structure

```
data/content.json            ← all editable text, grouped by page
public/media/                ← drop photos/video here (see MEDIA.md)
src/lib/content.ts           ← content model + read/write
src/lib/auth.ts              ← sessions, rate limiting
src/app/                     ← pages: /, /products, /contact, /about, /admin
src/app/sitemap.ts           ← sitemap.xml
src/app/robots.ts            ← robots.txt
src/components/              ← Nav, Footer, Media slots, tabs, form, motion canvas
src/app/globals.css          ← Tailwind v4 theme (design tokens)
```
